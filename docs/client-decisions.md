# Client decisions

The answers of Easy Office / Nexera to the questions of the specs and the launch plan, with what was done about each. Newest first.

## 16 October 2026

| Topic              | Decision                                                                             | Done                                                                                                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hosting            | Vercel, with Supabase for the database                                               | `vercel.json` and the "Vercel" section of `docs/deployment.md`                                                                                                                                    |
| Address            | `pos.nexerakw.com`                                                                   | To add under the Vercel project's domains                                                                                                                                                         |
| First brand        | Mudawara; its menu comes from its website                                            | Done: the website menu is in `apps/api/prisma/menus/mudawara.json` (22 dishes, 5 categories, extras and box choices) with the import `npm run menu:import`                                        |
| Loyalty            | 1 point per KWD paid; a point is worth 75 fils; points are not shared between brands | Defaults set (`defaultLoyaltySettings`); each brand can change them in Settings                                                                                                                   |
| Internet outage    | The tills should keep working without internet, but launch can go ahead without it   | Offline mode is the first work after launch                                                                                                                                                       |
| Printers           | A way to choose the printer                                                          | Waits for the printer model; the browser's print dialog chooses one today                                                                                                                         |
| Alerts             | The owner and the development team get them                                          | Void alerts go to the addresses in each brand's Settings → Alerts; system alerts on Vercel and Supabase once the addresses are known                                                              |
| Customer phones    | No consent step; numbers may be kept                                                 | Nothing to change                                                                                                                                                                                 |
| Till screen        | Stays signed in up to 24 hours, unless the team signs it out                         | `PIN_SESSION_HOURS` (24): a PIN session ends a day after it began                                                                                                                                 |
| Void reasons       | Late order; order is not right; food quality is not good; order is wrong             | The list of the void dialog; a free reason stays                                                                                                                                                  |
| KNET               | Connect the card machine later; the cashier types the slip number for now            | Nothing to change                                                                                                                                                                                 |
| Delivery platforms | API access for Talabat, Keeta and Jahez comes later                                  | Parked                                                                                                                                                                                            |
| Images             | The developers choose                                                                | Done: photos of dishes and brand logos are uploaded from the back office into Supabase Storage (`SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` on the server, "Settings" in `docs/deployment.md`) |
| Email              | The owner's own email account, set up by the client; the system needs a place for it | `SMTP_URL` and `ALERT_FROM` on the server (docs/deployment.md), used by the void alerts; purchase orders and password reset later                                                                 |
| Dine-in            | Split bills and ordering on a tablet are wanted                                      | A later phase                                                                                                                                                                                     |
| Opening hours      | Special hours for Ramadan and holidays are needed                                    | Done: special periods per branch under Opening hours                                                                                                                                              |
| Roles              | Only the owner manages roles; nobody makes their own                                 | The built-in roles stay                                                                                                                                                                           |
| Passwords          | Everyone but the owner must change their password at the first sign-in               | Done: the change-password screen, forced at the first sign-in                                                                                                                                     |
| Stock deduction    | Two options: when the order is paid, or when the kitchen starts it                   | Done: the brand setting "When does stock go down?" (Settings → Kitchen)                                                                                                                           |
| Refunds in reports | Counted on the day of the original sale                                              | Nothing to change                                                                                                                                                                                 |
| Voids              | A message to the owner at every void, and a dashboard view of voids by reason        | Done: an email per void to the brand's alert addresses, and "Voids today, by reason" on the dashboard                                                                                             |
